## RULING 1 — Unified attempt lifecycle (eliminates F4 permanently; resolves must-fix A1 + A2)
Re-authorization after ANY release ALWAYS mints a NEW attempt. There is no "same-attempt re-authorization." An `attempt` is one fulfillment try; once its hold is released (TTL / void / failure), that attempt is TERMINAL and can never be re-held or settled.
- `PAYMENT_VOID → retry` behaves EXACTLY like `REJECTED → retry`: new attempt = `attempt+1`, new manifest `mail_<letterId>_a<n>`, fresh `authorize` row with a real debit. W2's "same attempt reused" language is WRONG and is replaced everywhere.
- `DisputePackageLetter.attempt` is the single owner of the attempt integer and increments on every retry (schema: `@@unique([letterId, attempt])`, replacing `@@unique([letterId])`).
- W1's replay branch (§5.2) is corrected: it returns the existing row ONLY for a true idempotent replay (an `authorize` with NO `settle`/`release` sibling for that exact `(subject, attempt)`); if a `settle`/`release` sibling exists it REFUSES with `attempt_already_resolved`; and `requiredCents` is summed over ONLY the holds that do not already exist. There is no code path where re-authorization returns `ok:true` without a new debit against a fresh attempt.
- Result proof both docs must reproduce: after `release(mail_X,a1)`, `a1` is terminal → retry mints `a2` → `authorize(a2)` debits → `settle(a2)` requires `authorize(a2)`. No zero-net settlement exists.

## RULING 3 — N2 / provider-acceptance irreversibility (resolves must-fix A5, per the Founder decision)
Once a manifest reaches `PROVIDER_ACCEPTED`: the wallet hold is SETTLED and stays settled forever. `PROVIDER_ACCEPTED → CANCELED` is a FORBIDDEN transition in the Fulfillment Commitment layer (it would "pretend the mailing never occurred" — explicitly prohibited). Modeling:

Any operator "cancel" request after acceptance resolves ONLY to accounting reconciliation.
- Post-acceptance remediation vocabulary is `adjust` (owner-gated accounting compensation) ONLY — never `release`, never `clawback`-as-unwind, never a state that implies the letter was not mailed. Kai copy (W3) says the settled truth, never "nothing was charged."
- Physically removing `PROVIDER_ACCEPTED` from the shipped `CANCELABLE` array is a small product-code change flagged **FOUNDER-GATE (implementation phase)** — the architecture treats acceptance as irreversible regardless; this cycle documents the rule, does not touch product code.
