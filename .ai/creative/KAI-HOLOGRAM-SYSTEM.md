# Kai Hologram System (projection language — cinematic canon)

Kai never uses chat bubbles. **Everything Kai communicates is projected.** The IN-PRODUCT implementation is canonical in `KAI-PRODUCT-DESIGN.md` §6 (Kai Panels — real components, token-styled, honest data). THIS doc governs the same language at **cinematic grade** — for films, keynotes, ads, and the eventual high-fidelity product moments — so renders and product always rhyme. One grammar, two fidelities.

## Physical rules of the projection (permanent)
1. **Source:** projections emanate from a point ~30cm above Kai's head-line, slightly forward — light traceable back to him (a soft volumetric cone at cinematic grade; a subtle edge-glow in product). Kai LOOKS at what he projects; his gaze anchors the audience.
2. **Materialize:** 300–500ms — a thin teal baseline draws first, then the panel unfolds upward from it, data populating AFTER the frame exists (structure before content — the honesty beat). Dissolve is the reverse, faster (200ms).
3. **Materiality:** translucent ink-glass — navy glass panels, teal edge light, faint scanline texture at cinematic grade only; content is always crisp/opaque enough to read. Never sci-fi clutter, never floating debris, no glitch effects (glitch = untrustworthy).
4. **Physics:** panels are steady (a barely-perceptible 0.2° float at cinematic grade); they never wobble, spin, or orbit. MOTION-BIBLE easing throughout.
5. **One projection at a time.** A new one replaces the old via the baseline-draw. (Keynote exception: a projection may split into a maximum of three panels for a comparison beat, then re-merge.)
6. **Evidence-only.** Projections show data, documents, timelines, sources — never emoji, never decorative particles, never Kai's "feelings." If it isn't evidence or navigation, it isn't projected.

## The projection catalog (cinematic renditions of the §6 catalog — same seven, same data truth)
| Projection | Cinematic behavior |
|---|---|
| **Evidence sheet** (dispute/report items) | document panel; the disputed line HIGHLIGHTS with a slow teal underline draw; source citation chip docks bottom-right |
| **Cross-bureau grid** | three columns build left→right; agreeing cells settle dim; the conflict cell pulses ONCE in brand teal, then holds lit — the money shot of the whole brand |
| **Credit timeline** | horizontal light-spine draws; milestone nodes ignite sequentially with soft ticks; future nodes (deadlines) render hollow — filled vs hollow = done vs due |
| **Dispute flow** | letter silhouette → travel arc to a bureau glyph → 30-day arc-clock begins sweeping (the deadline radar attaches here) |
| **Letter generation** | grounded template lines draw in steadily FIRST, AI-refined lines shimmer in SECOND (the honest two-phase reveal, always in this order) |
| **Knowledge constellation** | question node center; source nodes (statute/library/community/Brief) light in true retrieval order; verified sources ring-badged |
| **Dashboard materialize** | keynote/ad only: the real product dashboard assembles from its actual components rising into place — never a fictional UI |

## Graph animation rules
Data draws at reading speed (bars grow 600ms, staggered 80ms; lines draw left→right 800ms) · axes and labels FIRST, data second · numbers count up only when the final value is the point (≤1s) · every chart carries its source chip · no rotating 3D charts, no infinite loops — a graph animates once, then is still.

## Sound (cinematic only)
One glassy materialize tone + sub-audible data ticks (CINEMATIC-BIBLE palette). Product implementation stays silent.

## Anti-drift
Any new projection type: added to `KAI-PRODUCT-DESIGN.md` §6 catalog FIRST (product truth), then rendered here at cinematic grade. Films never invent projections the product couldn't honestly have.
