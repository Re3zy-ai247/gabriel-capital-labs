3. TRUSTED-WRITER SEMANTIC ATTESTATION — BOUNDED

The hardened contract requires module-minted, verifier-backed repository reads with exact writer identity/version, semantic digest, source-set digest, and immutable snapshot identity. Raw, forged, stale, mismatched, and replayed inputs fail closed. Report-difference persistence candidates, score comparisons, ConsumerAssertion bindings, correspondence evidence, and human confirmations bind to the exact attested source set.

The durable source-set digest is value-free; plaintext score and comparable values are not persisted or logged by this attestation path. Ephemeral semantic verification may include values in memory only.

Explicit boundary: an authenticated production repository verifier/adapter is intentionally absent from dormant Phase 1.1. Schema validity and direct database access do not prove semantic authority or encrypted-value equality. The adapter must be separately implemented, authenticated, and attested before activation. Until then, the contract fails closed.

4. POST-I/O ARTIFACT TRUTH — CLOSED

Storage success is no longer proof of final artifact truth. The contract requires write → immutable readback → independent exact verification.

Before success, it verifies object identity, contract version, exact bytes, digest, recipient, bureau authority, ordered artifact membership, and readback time. Partial writes, substituted IDs, stale versions, wrong routing, wrong digests, and mismatched membership fail closed. Pure/local contracts do not gain unnecessary I/O.

5. NEGATIVE-INTEGRITY RESULT SHAPE — CLOSED

Artifact integrity is now a discriminated result: ARTIFACT_INTEGRITY_VERIFIED or ARTIFACT_INTEGRITY_FAILURE with an exact failure code.

Failure is structurally distinct from Clean, absent, unknown, parser uncertainty, deletion, unsupported, and not evaluated. Release is permitted only by the verified branch.

6. POSTGRESQL 40P01 HANDLING — CLOSED

Exact PostgreSQL 40P01 deadlocks become explicit rolled-back failures, never success. Default behavior is no retry. Retry requires frozen, module-minted verifier authority bound to the exact operation, idempotency key, semantic attestation, and retry class.

  • Retries are bounded with a hard ceiling of three attempts.
  • Exhaustion returns DEADLOCK_RETRY_EXHAUSTED.
  • No-authority deadlock returns DEADLOCK_DETECTED.
  • Ambiguous provider errors return TRANSACTION_OUTCOME_UNKNOWN and are not retried.
  • Messages are redacted; malformed and cyclic error shapes are bounded.

No production database caller was added. A disposable local replay exercised a real concurrent 40P01 at the unchanged Phase 1 schema boundary.

7. STRICT ISO PARSING — CLOSED

Strict calendar and offset validation rejects impossible dates, invalid leap dates, malformed offsets, ambiguous or missing required timezones, locale strings, trailing garbage, silent normalization, and unsupported timestamp precision.

Partial source dates stay explicitly partial/unknown. No exact date, timestamp, or precision is invented.

8. MALFORMED NESTED ARTIFACT VALIDATION — CLOSED

Authoritative nested inputs require exact plain-record shapes, required children, correct child types, exact allowed keys, valid bureau/recipient authority, consistent values, unique IDs and ordinals, bounded membership, and matching sequence/digest truth.

Malformed children, unexpected arrays/objects, duplicate IDs, contradictory values, invalid provenance/authority, oversized membership, and valid-looking outer objects with invalid inner authority are denied.
