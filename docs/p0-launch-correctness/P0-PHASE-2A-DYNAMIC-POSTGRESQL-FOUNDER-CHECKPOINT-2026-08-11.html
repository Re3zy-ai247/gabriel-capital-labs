Seal → append root cause and repair

A deferred parent check could be forced and discharged with SET CONSTRAINTS ALL IMMEDIATE. A later child inserted in the same transaction then needed its own proof that durable membership still fit the fixed parent count. Depending on the earlier parent event left a temporal seal-then-append gap.

The repair adds reverse child-triggered exact recounts. Valid atomic construction remains possible in either order while every later authoritative child must re-prove the source or confirmed-baseline count. All six post-set attacks reject with SQLSTATE 23514:

  1. source IdentityFact append;
  2. counted account pair append;
  3. source-listed account without counted presence;
  4. CONFIRMED-baseline IdentityFact append;
  5. category-completion append; and
  6. confirmed account-review membership append.

Both completeness-first and baseline/member-first valid construction orders pass.
