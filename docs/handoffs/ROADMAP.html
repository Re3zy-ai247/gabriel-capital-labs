Preserved subsystems

Named across the architecture package as things this program evolves, integrates with, or explicitly does not touch:

  • Wallet ledger — the subject of items 2 above; append-only, fold-derived, anchor-lock serialized.
  • Credit system (User.letterCredits) — coexists with, never replaced by, the Wallet; the two gate different Case Journey steps.
  • Provider abstraction — formalized, not redesigned, by A-PROVIDER-ABSTRACTION.md.
  • Fulfillment pipeline (lib/mail/*) — the spine this program evolves; "evolve THIS, never a parallel system."
  • Identity — the payer model integrates with existing lib/session.ts primitives without redesigning them.
  • Organizations — dormant Operator Identity/Organization/Membership tables named as out-of-scope; the agency-staff granularity residual is deferred to their activation.
  • Billing — the Stripe top-up branch reuses the existing one-time-payment shape and claim ledger verbatim.
  • Kai — narration and boundary laws extended, never redesigned.
  • Arena — named as a future consumer of Wallet cents, not designed here.
  • Mission Control — named as an existing precedent, not re-audited.
  • Operator Network — not addressed.
  • Growth Network — named as a reserved, undefined future funding surface.
