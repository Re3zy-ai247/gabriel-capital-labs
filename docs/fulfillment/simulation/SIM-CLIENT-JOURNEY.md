This file simulates the **designed target experience** (post-Phase-1, both Download and Send paths live), citing the doc/§ or file that grounds each scene's mechanics, and marks with `GAP:` anywhere the design is silent and a best-guess render was required.

**Protagonist:** Elena Ruiz, Meridian Credit Advisors' managed client, workspace run by staff operator **Marcus Webb**. Fixture locked by `SIM-BRIEF.md` §"Shared cast": a Northline Recovery Group collection ($1,842, original creditor Apex Card Services, disputed not-mine/unverifiable), a Meridian Bank Card charge-off ($3,205, re-aging indicators), and an unrecognized hard inquiry. Dates: Aug 18 – Oct 5, 2026 (this agent's assigned window inside the shared cast's Aug 12 – Oct 5 span). Wallet: Meridian's agency wallet pays — Elena's own dispute never touches a wallet of her own (`WALLET-COMMITMENT-MODEL.md` §9.1: *"there is no per-client Wallet for agency-managed packages"*).

**A load-bearing structural fact, established once here rather than re-argued every scene:** `Case` is scoped **per-`(User, Tradeline)`, not per-user** (`A-DOMAIN-MODEL.md` §1.3, argued explicitly against a whole-client Case: *"the existing waiting-period clock runs per letter/per tradeline, not per user; a user-wide Case would force an artificial single 'state' across tradelines that are in genuinely different rounds"*). Colloquially "Elena's case" is therefore **two independent `Case` identities** running concurrently — one anchored to the Meridian Bank Card charge-off, one to the Northline Recovery Group collection — that happen to converge into **one Dispute Package** for Round 1 mailing efficiency, then diverge again the moment their outcomes differ. The scenes below are told in true chronological order (not strictly the brief's prose order) precisely so this divergence renders honestly instead of as one tidy story; a node index follows for navigation against the brief's canonical list.

1. **[GAP — Critical] No client-facing view exists anywhere in the reviewed architecture.** Elena Ruiz — the actual consumer, the person whose credit file and statutory rights this entire system exists to act on — has no login, no case-status page, no notification, no evidence export (Scenes 1, 22). 2. **[GAP — High] The on-behalf-of money-narration voice, designed in real depth (`KAI-FULFILLMENT-UX.md` §2.2–§3.4), has no audience that can read it today** (Scene 8).
